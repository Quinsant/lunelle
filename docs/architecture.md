# Architecture

The Cargo workspace separates `lunelle-core` (IDs, geometry, runtime, window and renderer APIs), `lunelle-css` (stylesheet parsing and a deliberately limited cascade), `lunelle-aom` (component tree and immutable style snapshots), and `lunelle-macros` (`view!` and function-component helpers). Dependency direction is application -> AOM -> core/CSS; CSS -> core is optional and it must not depend on AOM. Worker results carry snapshot versions; only the UI owner applies matching results.

The current CSS profile supports stylesheet syntax parsing through `cssparser`, including declaration recovery, `!important`, nested `@media`, and source-order tracking, as well as type, class and ID selectors, compound selectors, selector lists, descendant and child combinators, specificity, and inherited values for common text properties. The CSS crate owns rule/declaration parsing, media conditions, selector parsing, specificity, and matching over immutable `SelectorNode` data. Application reuses the shared selector API while validating its supported properties, adding interaction state, and applying richer values to its render/layout tree; the neutral CSS cascade remains a smaller subset. Unsupported syntax is reported through diagnostics; this is not a complete browser CSS implementation. AOM snapshots retain element IDs, compute against immutable CSS inputs, and tag results with the snapshot version so callers can reject stale results. Component rerenders retain IDs for same-tag children by explicit `with_id` key across reordering, with positional matching for unkeyed children.

The core's `window-winit` feature provides both a polling window adapter and a callback-driven application lifecycle that owns winit event-loop startup and normalizes window events. Core owns backend-neutral frame renderer lifecycle/shape-command contracts and a basic wgpu renderer for solid rectangles. `Runtime` supports cooperative task cancellation and joins workers on shutdown; UI callbacks are processed only by its owner thread. `#[component]` currently supports nongeneric synchronous functions with one `Clone + 'static` props argument and `Element` return type; generated component messages replace those props.

The root package is a thin facade over `lunelle-application`, which composes Core, CSS, AOM, and macros. The application crate provides a builder for window options, stylesheets, and a root AOM component, then hands the configuration to an `ApplicationRunner`; platform-specific runners are supplied separately. AOM owns component state/lifecycle, element trees, events, accessibility, and immutable style snapshots. CSS parses stylesheets and computes supported cascade values. The [counter example](../examples/counter.rs) demonstrates a stateful macro component, pointer events, CSS styling, AOM diffing, and native rendering. Other examples cover a [form](../examples/form.rs), [list](../examples/list.rs), [background task](../examples/background_task.rs), and [modular crates](../examples/modular_crates.rs); see the guides for [components](components.md), [signals](signals.md), [concurrency](concurrency.md), the [CSS profile](css-profile.md), [macro testing](macro-testing.md), [platform support](platform-support.md), and the [dependency audit](dependency-audit.md). Native window/GPU runtime tests remain outstanding; CI runs cross-platform compile/test jobs.
